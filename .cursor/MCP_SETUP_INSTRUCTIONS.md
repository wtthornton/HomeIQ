# MCP Configuration Setup

**Created:** January 2025
**Updated:** July 2026
**Purpose:** How the NLT MCP servers are wired into HomeIQ for Cursor and Claude Code.

---

## 1. The NLT MCP servers

HomeIQ uses the six-server NLT plugin bundle. These replaced the older single
`tapps-mcp` + `docs-mcp` monolith pair.

| Server | Purpose |
|---|---|
| `nlt-build` | Code quality scoring, security scanning, quality gates, doc lookup |
| `nlt-memory` | Cross-session project memory |
| `nlt-setup` | Project profiling and bootstrap |
| `nlt-linear-issues` | Linear epic/story read + write |
| `nlt-project-docs` | Doc generation, artifact validation, planning helpers |
| `nlt-release-ship` | Release updates and shipping workflow |

### Requirements

- Global CLIs on `PATH`: `tapps-mcp`, `tapps-platform`, `docsmcp`
  (installed to `~/.local/bin`).
- No per-project checkout is needed — the servers run from the globally
  installed binaries.

### Configuration

Both config files are **generated** — do not hand-edit them. Regenerate with:

```bash
tapps-mcp init --host cursor      --project-root . --force   # -> .cursor/mcp.json
tapps-mcp init --host claude-code --project-root . --force   # -> .mcp.json
```

- **Cursor** (`.cursor/mcp.json`) launches each server through a wrapper script
  in `.cursor/bin/<server>-serve.sh`. The wrappers source operator secrets
  before spawning, so Cursor does not need the keys in its own environment.
- **Claude Code** (`.mcp.json`) invokes the global binaries directly with a
  `--profile <server>` argument.

### Tool names

Tools are namespaced by server, for example:

- `mcp__nlt-build__tapps_session_start`
- `mcp__nlt-build__tapps_quick_check`
- `mcp__nlt-build__tapps_validate_changed`
- `mcp__nlt-memory__tapps_memory`
- `mcp__nlt-project-docs__docs_generate_readme`

The legacy `mcp__tapps-mcp__*` and `mcp__docs-mcp__*` names are gone. Some
generated hooks still match the old names alongside the new ones for
backwards compatibility; that is intentional.

## 2. Secrets

**Never commit keys.** All MCP config entries reference environment variables
via `${VAR}` interpolation.

| Variable | Used for |
|---|---|
| `TAPPS_MCP_CONTEXT7_API_KEY` | Live library docs via Context7 (`tapps_lookup_docs`) |
| `TAPPS_BRAIN_AUTH_TOKEN` | tapps-brain HTTP memory backend (only in HTTP mode) |

Set them in `~/.tapps-operator.env`, which the Cursor serve wrappers source
automatically:

```bash
# ~/.tapps-operator.env
export TAPPS_MCP_CONTEXT7_API_KEY="ctx7sk-..."
export TAPPS_BRAIN_AUTH_TOKEN="..."
```

For Claude Code, export the same variables from your shell profile
(`~/.bashrc` / `~/.zshrc`) so they are present when the server is spawned.

---

## 3. Hooks

Hooks are POSIX shell scripts, not PowerShell:

- Claude Code: `.claude/hooks/*.sh`, wired in `.claude/settings.json`
- Cursor: `.cursor/hooks/*.sh`, wired in `.cursor/hooks.json`

They are regenerated by `tapps-mcp init` / `tapps-mcp upgrade`.

---

## 4. Verification

```bash
tapps-mcp doctor          # full config / hook / tooling diagnostic
```

Then start a session in Cursor or Claude Code and call `tapps_session_start`.
It should return server info and the project profile.

A missing `.vscode/mcp.json` is expected — HomeIQ configures Cursor and Claude
Code only. Add it with `tapps-mcp init --host vscode --project-root . --force`
if you also use plain VS Code.
