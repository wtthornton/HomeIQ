# orchestration-prompt learnings (project-scoped)

Append one-line lessons as you generate prompts. Keep them project-scoped; never
bleed across repos. This file is created once by the scaffolder and never
overwritten on upgrade — it's yours.

<!-- - Validation goals need a verified-correct-negative Done-when, or the loop chases an unreachable target. (2026-06-18) -->
- HomeIQ harness gates the loop must pre-satisfy: `save_issue` needs a `docs_validate_linear_issue` sentinel <30min (use the `linear-issue` skill), `list_issues` needs a prior `snapshot_get` (use `linear-read`), and all `tapps_*` MCP tools need `tapps_session_start` first. (2026-08-01)
- Merged != live here in a second way: several HomeIQ compose services declare `build:` with no `image:`, so `docker buildx bake` output is NOT what compose runs — rebuild via `docker compose up -d --build <service>` or the loop verifies a stale container. (2026-08-01)
- When the user has said "do not set anything up", split the Done-when between *agent implemented and tested* (fixtures/simulator) and *agent applied to the live system* (Autonomy hard-stop) — otherwise the loop mutates production to score itself green. (2026-08-01)
- Validation-goal caveat for audit tooling: an `audit` that reports every recipe NEEDS_APPLY is a correct pass, not a failure — state this explicitly or the loop chases an unreachable all-green. (2026-08-01)
- The skill's own files are tapps-managed (BEGIN/END markers) — customizing them without adding an `upgrade_skip_files` entry in `.tapps-mcp.yaml` means the next `tapps_upgrade` silently reverts the work. (2026-08-01)
- The `uv run tapps-mcp memory search` CLI is broken in this project (raises `ValueError: MemoryStore requires a Postgres private_backend`) — emit the `tapps_memory` MCP tool call for brain recall, never the CLI form. (2026-08-01)
- Pair every must-reach-zero clause with a must-grow one drawn from the SAME work: "0 REST-registry callers" alone is satisfiable by deleting the callers, so it must carry "AND >= N services import the shared client". Same for "0 deviations" → "at >= N rows". (2026-08-01)
- When a sub-goal's correct outcome is sometimes *removal* (a frontend call with no backend route), say so in Guardrails under "caps must not fire on correct behaviour" — otherwise the verifier scores a correct deletion red and the loop re-adds dead code. (2026-08-01)
- Order a long migration cheapest-and-least-coupled first, and say why: a 6-hour run that truncates should leave whole services done rather than every service half-done. (2026-08-01)
- Rate limits are a correctness trap in sweep scripts: admin-api caps at 60 req/min and `verify-dashboard-contract.sh` paces at 1.1s, so the prompt must forbid lowering `CONTRACT_PACE` to "speed it up" — the resulting 429s look exactly like failures. (2026-08-01)
- Carry an explicit "out of scope — human-gated, do not attempt" list naming the blocked issue ids; a loop told only what to do will wander into the blocked work and burn the run rediscovering the gate. (2026-08-01)
- ALWAYS read the full open backlog (`linear-read` over the whole project) before scoping a prompt — scoping to "the issues this session produced" missed 5 of 6 open HomeIQ epics and ~37 stories, and got the ordering wrong: the foundational build/CI epic was invisible. (2026-08-01)
- Verify the foundation epic's claims with a grep before assigning wave order: "all 54 build contexts are `../..`" and "0 of 10 domain CI workflows trigger on pull_request" are what justify putting build decoupling first, and both took one command each. (2026-08-01)
- When a Done-when clause measures a count going DOWN (containers 58→11, repo-root contexts 54→0), pair it with a capability-preservation clause ("every retired service's capability proven reachable", ">=54 services still build") — otherwise the target is met by deleting the system. This is the mirror of the must-grow rule. (2026-08-01)
- Order destructive waves last and make each deletion an Autonomy hard-stop; a consolidation epic that runs before its replacement surface exists is an outage, not a refactor. (2026-08-01)
- Subagents spawned as `general-purpose` have write tools even when the prompt says "read-only" — one silently edited `health-dashboard/src/services/api.ts` during a prompt-writing turn. Check `git status` after any subagent fan-out, and use the `Explore` agent type (no Edit/Write) for genuinely read-only research. (2026-08-01)
- A `haiku` verifier asked an open-ended gating question ("any new CI failures from this PR?") returned a confident WRONG verdict — "NO NEW FAILURES" while a check on the exact changed path was failing because of the PR — and skipped the log-fetch it was explicitly told to run. The same model answering a narrowed question ("does the ruff-format step pass?") was correct. Tier by question shape: cheap for closed evidence-checkable questions, `opus` for anything gating. (2026-08-11)
- `effort` is a Workflow-only parameter: `Agent(...)` accepts `model` but not `effort` and inherits the session's. A prompt that writes "use high effort" on an Agent dispatch is a no-op — if per-step effort matters, that step must run inside a Workflow. (2026-08-11)
- Never trust a subagent's *conclusion* on a load-bearing question; re-derive it from the evidence it returned. The CI agent's verdict was wrong but its raw job-status table was correct — reading that table directly surfaced the one failing step that was genuinely mine. (2026-08-11)
- Before/after quality comparisons must confirm which branch the working tree is on: a post-merge `git checkout` of the old feature branch made "before" and "after" score identical files, producing a fake "no change" result. Identical scores to 4 significant figures is the tell. (2026-08-11)
- Emitted prompts must explicitly GRANT the research tools and name the required lookups; a prompt that omits this gets HA/library YAML written from recalled syntax. `tapps_lookup_docs` is Context7-backed and local-cache-first, so "conserve lookups" is never a reason to skip it. (2026-08-11)
- Research before designing, not after: one `tapps_research` call replaced a hand-rolled multi-sensor entity list with HA's Binary sensor group helper (any-on/all-off semantics for free) and surfaced that labels are first-class automation targets — which is what makes "adopt a new sensor with no automation rewrite" actually true rather than aspirational. (2026-08-11)
- For HA specifically, always confirm the automation schema generation before writing YAML: 2024.10+ uses plural `triggers:`/`conditions:`/`actions:`, and a prompt carrying the legacy singular form will lint clean and fail at runtime. (2026-08-11)
- **AgentForge is where this project's intelligence belongs.** A prompt that routes reasoning through a HomeIQ container (`ha-ai-agent-service`, `ai-core-service`, `ai-query-service`) is building the thing TAP-5300/TAP-5302 exist to retire. The split is pipeline+gateway: AF reasons (author/judge/analyse), HomeIQ acts (collect, call HA, lint, deploy, test, roll back). Check every emitted prompt for cognition that leaked into a consumer service. (2026-08-11)
- 17 `expert-*` agents are published platform-wide on AF (architecture, testing, security, performance, database, api-design, observability, ux, …) and cost nothing to author — consult them during planning and review, and record where the advice was rejected. Other consumer projects also carry their own domain experts (`web-store-wstore-expert-*`, `hearth-goods-hearth-expert-*`); HomeIQ has none yet, which is the gap worth closing. (2026-08-11)
- The `agentforge` MCP server caches `.env` at startup: after restoring or rotating `AGENTFORGE_API_KEY`, its tools keep returning `missing-bearer` until the server restarts, while `scripts/af.sh` and curl work immediately. Do not diagnose that as a bad key. (2026-08-11)
- AF workflow authoring traps worth restating in any emitted prompt: `kind: task` not `kind: agent`; `$input` refs — a `{{input}}` placeholder passes through **literally** and `spec_version: 2` strictness will not catch it; terminal state is `complete` not `success`; `output_schema` is enforced on the workflow node, not the agent frontmatter; publish agents before workflows or get a 422. (2026-08-11)
- `run_config_flow` raises `HAHumanGateRequired` on ANY `progress` step, but not every progress step is a human gate: ZHA's `form_new_network` is pure hardware I/O (~2.5 min, poll with empty POSTs until `create_entry`). Prompts wiring config-flow recipes must distinguish poll-able progress from genuine human gates, or formation gets mis-filed as HITL. (2026-08-11)
- When a live install already happened, the captured flow transcript IS the recipe spec — cite the real per-step payloads (e.g. ZHA `choose_serial_port` takes a plain `{"path": "socket://ip:6638"}`) instead of telling the loop to re-derive schemas from core source. Also encode the destructive inverse as a guardrail: re-running ZHA formation on a loaded entry orphans every paired device. (2026-08-11)
- HA label registry stores slug ids while HomeIQ's store keeps `prefix:name` strings; any recipe/prompt that round-trips labels must match by name OR slug before creating, else every re-apply mints `<slug>_2` duplicates. (2026-08-11)
- A generated prompt can already exist from a prior session (committed under prompts/) — check `git log prompts/` and grep before generating; regenerating a near-duplicate forks the SoT. The right move is execute-or-update, not re-emit. (2026-08-11)
- AF judge agents hallucinate findings against their own input: the org-manifest judge asserted 5 entities were "absent" that were present with the exact recommended labels. Every emitted prompt that dispositions judge findings must require a deterministic re-check against the artifact BEFORE amending — reject-with-evidence is a first-class disposition. (2026-08-11)
- AF expert invocations can return degenerate output ({"advice":"test"}) at full billed cost; retry once with an explicit anti-placeholder instruction before falling back to codebase-convention reasoning. (2026-08-11)
- The tapps quality gate's maintainability category is module-length-dominated (radon MI ~0 past ~800 lines): plan NEW recipe/feature code as small cohesive modules re-exported from the legacy hub file, or the gate fails on size alone and tempts a suppression. Name-matched test files (test_<module>.py) are what the test-coverage category detects. (2026-08-11)
- Engine apply() halts later phases on any BLOCKED_ON_HUMAN in the current phase — a full-stack converge stops at the HACS gate before phase 6. Scope live converges per-phase (curl body {"phase": N}) so the halt is a finding, not a lost run. (2026-08-11)
- When a companion agent is still filing tickets mid-generation, put the pending ids in Unverified assumptions with a self-healing confirm step — then resolve them in-session the moment the filing notification lands, so the emitted prompt ships with concrete ids. (2026-08-12)
- A long-lived (>600k-token) goal-loop agent becomes disproportionately vulnerable to 529 Overloaded kills; the burndown prompt caps runs and checkpoints to brain per wave so a fresh session resumes cheaply instead of resuming the giant transcript. (2026-08-12)
- Physical-world steps (pairing buttons, sensor placement, switch wiring) are a distinct Autonomy hard-stop class: the loop must surface them as readiness gates and wait, never simulate or skip — 2026-08-12's manual run is the reference protocol (now on TAP-5946). (2026-08-12)
- When a prompt's purpose is Linear closures, Sub-goal 0 must probe the Linear plugin's auth FIRST (ToolSearch for a plugin tool) and hard-stop-once if absent — OAuth is user-only, not self-healing; the 2026-08-13 session completed and verified the work but could not close the issues, and the loop's rules (get_issue before citing) blocked the next story too. (2026-08-13)
- Acceptance criteria must not freeze live-derived counts: "12 queue items" failed verification because the count drifts with discovery flows (and the 12th DOM card was static markup). Anchor to the system's own self-report (status line, `.items|length`) and name the correct JSON key — the wrong key (`.queue`) silently returned 0 instead of erroring. (2026-08-13)
- A resumed/rewritten drain prompt must re-verify PR + branch state live at rewrite time, not trust the handoff: PR #82 went from "OPEN, merge pending" in the handoff to MERGED within the hour, flipping the branch-base rule from "branch off the feature tip" to "branch off master". Bake `git merge-base --is-ancestor HEAD origin/master` into Sub-goal 0. (2026-08-13)
- The pre-identified decide-trap pattern works: TAP-5430's write-mechanism question fired exactly as the prompt predicted (design rows named only the add-on family; live `core_ssh` options showed empty authorized_keys/password at key-name level). Baking "check X, surface if undecided, batch the hard-stop" into a prompt converts a mid-run stall into a 15-minute recorded skip. (2026-08-13)
- Ticket `file.py:LINE` anchors rot when modules get split (recipes.py 822→410 lines made TAP-5431's three anchors all stale); a drain prompt should say "anchors are hints — re-locate symbols by grep before trusting line ranges". (2026-08-13)
- A refute-verifier finding a scan's own carve-out (`.example` excluded from the credential sweep) and proving it with a plant is the highest-value verifier behavior observed so far — prompts should explicitly invite verifiers to attack the FIX's coverage, not just the fixed instances. (2026-08-13)
- `docker compose up -d` without a config delta silently does NOT recreate the container; post-change redeploy evidence requires `--force-recreate` (a verifier caught StartedAt predating the commit by 22 minutes). (2026-08-13)
- First-run CI for previously-unguarded suites WILL find rot — plan for it: the libs-ci story budgeted a local dry-run first (caught homeiq-resilience's sync-calls-on-async-API + a brittle `len(__all__)` pin) and the live first run still caught more (an undeclared `requests` dependency that only resolved by local-venv coincidence). Treat "new CI goes green on the first try" as a smell, not a goal. (2026-08-13)
- Long HA-integration applies (HACS install + restart + discovery) need the client stack audited for restart-survival up front: transport errors unwrapped by rest clients, no WS auto-reconnect, and flow/progress hiding user-source flows server-side each cost a live round. A prompt can pre-grant this checklist: suppress-and-poll the restart call, poll /api/config for state==RUNNING after a min-wait, ws.close()+connect() after reboot, restart-and-retry on already_in_progress. (2026-08-13)
- HomeIQ is ALREADY a DNA species (24 genes + 7 workflows live, `dna-core/species/homeiq.yaml`). A prompt scoped as "build the reasoning" duplicates published capability — run `list_agents(project_slug="homeiq")` and read `dna-core/` BEFORE scoping any intelligence work. Three of my "new" capabilities already existed as genes. (2026-08-19)
- The AF integration direction here is **AF → HomeIQ over MCP**, not HomeIQ → AF. Grepping HomeIQ services for `invoke_task` finds nothing and looks like "AF is unwired" — the truth is in `docker logs homeiq-mcp`, where cron-shaped traffic (every 6h + a 07:00 spike) proves three chromosomes are live. Check the MCP server's logs before claiming either direction is dead. (2026-08-19)
- Read in-progress epics' CHILDREN, not just top-level issues: TAP-6230 was In Progress with 7 open children covering naming/area, and two of them were duplicated into a freshly-authored epic before the full backlog read caught it. The existing sub-issue is the unit of duplication, not the epic. (2026-08-19)
- `hiq-correlate` cannot be repointed at non-energy correlation — its output_schema hard-requires meter fields, and the shared genome README explicitly prices `correlate` as the per-domain outlier (~42% shared vs 72.9% average). When a prompt needs a fan-in aggregator for a new domain, author a new gene; bending `correlate` fights a documented design decision. (2026-08-19)
- Never let a friendly name gate a decision on this instance: two identically-modelled VZM31-SN dimmers carried swapped names and wrong areas, and `area_entities("office")` did not return the switch powering the office. Emitted prompts must name the identity test (ieee, LED-bar colour probe, or behavioural correlation) rather than saying "find the office switch". (2026-08-19)
- Prove a gate is WIRED by breaking it, never by grepping for the module name. I reported the dna-core drift gate "NOT WIRED" because `validate.py` contains no string `render_dna_core` — it calls `check_dna_core()`, which imports it. A one-line mutation to a `.tmpl` settled in seconds what the grep got backwards. Emit prompts that ask for a failing artifact, not a matching line. (2026-08-19)
- A gate that iterates a collection passes VACUOUSLY when the collection is empty, and that is the most dangerous green there is. `dna-core/packs/` did not exist, so `render_packs()` looped over nothing, returned `{}`, and the drift check compared an empty mapping and passed. Every "for x in collection: check(x)" gate needs an explicit non-empty assertion beside it. (2026-08-19)
- A NOT NULL column can still carry zero information — check the DISTRIBUTION, not the constraint. `device_entities.domain` was the literal string `'unknown'` on all 768 rows because the code asked HA's entity-registry payload for a `domain` key it does not serialise, and the downstream fallback `e.domain or <derive>` never fired because `"unknown"` is truthy. One `GROUP BY` would have found it any time in the preceding months. (2026-08-19)
- Corroboration that a rename can erase is not independent of names. Hue room-group membership looked like genuine upstream evidence for "which room is this bulb in" — until you notice the group lists member NAMES, not stable ids. Anything keyed on a string the defect can change is the defect wearing a better label. (2026-08-19)
- Do not mint an evidence class for the ABSENCE of evidence. A `name_match` class would sort above `unverified` and read as established; keeping the vocabulary at measured > upstream_source > attestation > unverified and recording the name echo in a free-text `method` field makes "we do not know" unpromotable by construction. (2026-08-19)
- Fixing the exception is not fixing the function. The naming endpoints 500'd on a missing attribute; making them return 200 would have shipped scores where `friendly_name` was 0 for entities that plainly have one, because HA COMPOSES friendly_name from the device name and never stores it. A prompt that says "fix the 500" gets a 200; say "and the numbers it returns must be defensible". (2026-08-19)
- When a gateway exists and the bug persists, suspect ORDER and DEFAULTS before absence. `accept_suggested_name` committed the rename to HomeIQ's DB and only then attempted the HA write — with `sync_to_ha` defaulting to FALSE at both the API and the frontend. The gateway was imported and correctly used elsewhere in the same file; nothing was missing, the sequence was backwards. (2026-08-19)
- Treat every factual premise in a generated prompt as a hypothesis with a cheap test. Three of this one's load-bearing claims were false: the drift gate was already wired, `homeiq-ha-automation-tester` was described as "complete" but failed the kit validator on two missing frontmatter fields, and VAL-005's key was unimplementable. Budget the first iteration for premise-checking rather than building on them. (2026-08-19)
- Never write a VAL that names a UNIQUE key without checking the upstream system's own uniqueness contract first. VAL-005 demanded a UNIQUE index on `unique_id` alone; HA keys its entity registry on `(domain, platform, unique_id)` and 21 pairs on this instance legitimately share a `unique_id` (`core_ssh_state` belongs to both a switch and a binary_sensor). The intent was right and the column list was unimplementable — a contract can be wrong without the implementation being broken. (2026-08-19)
- `docker exec` WITHOUT `-i` silently discards a heredoc: psql receives nothing, does nothing, and exits 0. A migration reported success and changed not one row. Any prompt step that pipes SQL or Python into a container must say `-i`, and must verify the END STATE rather than the exit code. (2026-08-19)
- Ask the adversarial verifier to attack the weakness YOU already suspect, by name. Naming the Hue name-keyed join as the thing to attack hardest got a decisive refutation back instead of three paragraphs of agreement — and it was right, so 23 rows lost their actionable flag. A verifier told "check this" confirms; one told "refute this specific claim" investigates. (2026-08-19)
- STANDING RULE (owner, 2026-08-19): a friendly name is for talking to the customer and NEVER for the system. It may be rendered to a person, scored as a customer-facing artifact, and matched against what a person typed — then it must resolve to a stable id immediately. It may never be a join key, an identifier, or an input to a decision the system makes on its own. Codified in `.claude/rules/friendly-names.md`. (2026-08-19)
- The dangerous violation is never a bare `name ==` — it is a name match ONE HOP REMOVED wearing a better label. Hue room-group membership read as independent upstream corroboration of a bulb's room; the group lists member NAMES, so a rename erases it. The test to apply to any corroborating signal is "would a rename break this?" — if yes it is the name, and it confers nothing. (2026-08-19)
- Auditing for this rule, the highest-yield greps are area/room INFERENCE, not identity: `area.*in .*name`, `infer.*area`, `area_from`, `_area\(.*name`. That found a suggestion engine scoring 100% confidence for "the area name appears in the entity_id", whose output fed a `>= 80` gate that flagged the registry as wrong and reached a path writing an area to HA — a renamed device could relocate itself. (2026-08-19)
- When capping a name-derived score, cap it BELOW the consuming threshold and pin that relationship in a test naming the threshold, not the constant. Capping alone silently turns the consumer's branch into dead code; the honest move is to keep the signal, rename the category from an assertion (`incorrect_area_assignment`) to an observation (`name_area_mismatch`), and preserve the RANKING so the engine is still useful to the human it was always for. (2026-08-19)
- An existing drain prompt can be the SoT and still be BLIND to a whole wave: `homeiq-backlog-drain.md` (synced 2026-08-17) references zero of the TAP-61xx/62xx defect stories (one grep proved it). The right move was a complementary prompt with an explicit disjoint-scope header naming the other as epic-wave SoT — not a rewrite that forks 50 issues of stale state. (2026-08-19)
- When the generating session itself landed fixes, make "verify-and-close what master already fixed" Sub-goal 1 and name the commit SHAs — cheapest wins first, and it stops the next session from re-implementing landed work. Symmetrically: closing is not automatic — each needs the refute-style verifier pass, and an epic (TAP-6255) gets an evidence COMMENT, not a close. (2026-08-19)
