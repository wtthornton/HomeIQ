# orchestration-prompt learnings (project-scoped)

Append transferable lessons as you generate prompts, project-scoped — never bleed
across repos. Created once by the scaffolder; never overwritten on upgrade — it's yours.

- **Reading CI status has six traps — keep the detector commands.** (1) `gh pr checks` renders *cancelled* as fail; split with `gh api repos/<o>/<r>/commits/<sha>/check-runs`, read `.conclusion`. (2) An ABSENT check-run isn't a pass — `paths:` filters skip whole workflows; compare against `gh run list --workflow=<file> --branch master`, not the head commit's set. (3) Check-runs take ~6+ min to appear — `gh run list --branch` can read empty while `gh pr checks <n>` lists queued jobs; ask it first. (4) Find the failing STEP: `gh api repos/<o>/<r>/actions/runs/<id>/jobs -q '.jobs[]|select(.conclusion=="failure")|{name,steps:[.steps[]|select(.conclusion=="failure")|.name]}'` — TAP-6564's "2 critical npm vulns" was a passing Trivy step dying on `upload-sarif`, lacking `permissions: security-events: write`. (5) Check the workflow's `on:` block: `docker-security-scan.yml` (`pull_request`+`schedule`, no `push`) — a green run says nothing about a `schedule`-only failure, and merging never re-triggers master's runs; verify via `gh workflow run <file> --ref master`. (6) Step TIMING is free: a job failing 14s after creation cannot have built 39 services. (2026-08-23, extended 2026-08-26)
