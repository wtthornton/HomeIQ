# orchestration-prompt learnings (project-scoped)

Append one-line lessons as you generate prompts. Keep them project-scoped; never
bleed across repos. This file is created once by the scaffolder and never
overwritten on upgrade — it's yours.

- Rate limits are a correctness trap in sweep scripts: admin-api caps at 60 req/min and `verify-dashboard-contract.sh` paces at 1.1s, so the prompt must forbid lowering `CONTRACT_PACE` to "speed it up" — the resulting 429s look exactly like failures. (2026-08-01)
- Carry an explicit "out of scope — human-gated, do not attempt" list naming the blocked issue ids; a loop told only what to do will wander into the blocked work and burn the run rediscovering the gate. (2026-08-01)

- When a Done-when clause measures a count going DOWN (containers 58→11, repo-root contexts 54→0), pair it with a capability-preservation clause ("every retired service's capability proven reachable", ">=54 services still build") — otherwise the target is met by deleting the system. - Order destructive waves last and make each deletion an Autonomy hard-stop; a consolidation epic that runs before its replacement surface exists is an outage, not a refactor. (2026-08-01)

(2026-08-11)

- A gate that iterates a collection passes VACUOUSLY when the collection is empty, and that is the most dangerous green there is. `dna-core/packs/` did not exist, so `render_packs()` looped over nothing, returned `{}`, and the drift check compared an empty mapping and passed. Every "for x in collection: check(x)" gate needs an explicit non-empty assertion beside it. (2026-08-19)
- A NOT NULL column can still carry zero information — check the DISTRIBUTION, not the constraint. `device_entities.domain` was the literal string `'unknown'` on all 768 rows because the code asked HA's entity-registry payload for a `domain` key it does not serialise, and the downstream fallback `e.domain or <derive>` never fired because `"unknown"` is truthy. One `GROUP BY` would have found it any time in the preceding months. (2026-08-19)
- Corroboration that a rename can erase is not independent of names. Hue room-group membership looked like genuine upstream evidence for "which room is this bulb in" — until you notice the group lists member NAMES, not stable ids. Anything keyed on a string the defect can change is the defect wearing a better label. (2026-08-19)
- Do not mint an evidence class for the ABSENCE of evidence. A `name_match` class would sort above `unverified` and read as established; keeping the vocabulary at measured > upstream_source > attestation > unverified and recording the name echo in a free-text `method` field makes "we do not know" unpromotable by construction. (2026-08-19)
- Fixing the exception is not fixing the function. The naming endpoints 500'd on a missing attribute; making them return 200 would have shipped scores where `friendly_name` was 0 for entities that plainly have one, because HA COMPOSES friendly_name from the device name and never stores it. A prompt that says "fix the 500" gets a 200; say "and the numbers it returns must be defensible". (2026-08-19)
- When a gateway exists and the bug persists, suspect ORDER and DEFAULTS before absence. `accept_suggested_name` committed the rename to HomeIQ's DB and only then attempted the HA write — with `sync_to_ha` defaulting to FALSE at both the API and the frontend. The gateway was imported and correctly used elsewhere in the same file; nothing was missing, the sequence was backwards. (2026-08-19)
- Treat every factual premise in a generated prompt as a hypothesis with a cheap test. Three of this one's load-bearing claims were false: the drift gate was already wired, `homeiq-ha-automation-tester` was described as "complete" but failed the kit validator on two missing frontmatter fields, and VAL-005's key was unimplementable. Budget the first iteration for premise-checking rather than building on them. (2026-08-19)
- Never write a VAL that names a UNIQUE key without checking the upstream system's own uniqueness contract first. VAL-005 demanded a UNIQUE index on `unique_id` alone; HA keys its entity registry on `(domain, platform, unique_id)` and 21 pairs on this instance legitimately share a `unique_id` (`core_ssh_state` belongs to both a switch and a binary_sensor). The intent was right and the column list was unimplementable — a contract can be wrong without the implementation being broken. (2026-08-19)
- `docker exec` WITHOUT `-i` silently discards a heredoc: psql receives nothing, does nothing, and exits 0. A migration reported success and changed not one row. Any prompt step that pipes SQL or Python into a container must say `-i`, and must verify the END STATE rather than the exit code. (2026-08-19)
- Ask the adversarial verifier to attack the weakness YOU already suspect, by name. Naming the Hue name-keyed join as the thing to attack hardest got a decisive refutation back instead of three paragraphs of agreement — and it was right, so 23 rows lost their actionable flag. A verifier told "check this" confirms; one told "refute this specific claim" investigates. (2026-08-19)
- STANDING RULE (owner, 2026-08-19): a friendly name is for talking to the customer and NEVER for the system. It may be rendered to a person, scored as a customer-facing artifact, and matched against what a person typed — then it must resolve to a stable id immediately. It may never be a join key, an identifier, or an input to a decision the system makes on its own. Codified in `.claude/rules/friendly-names.md`. (2026-08-19)
- The dangerous violation is never a bare `name ==` — it is a name match ONE HOP REMOVED wearing a better label. Hue room-group membership read as independent upstream corroboration of a bulb's room; the group lists member NAMES, so a rename erases it. The test to apply to any corroborating signal is "would a rename break this?" — if yes it is the name, and it confers nothing. (2026-08-19)
- Auditing for this rule, the highest-yield greps are area/room INFERENCE, not identity: `area.*in .*name`, `infer.*area`, `area_from`, `_area\(.*name`. That found a suggestion engine scoring 100% confidence for "the area name appears in the entity_id", whose output fed a `>= 80` gate that flagged the registry as wrong and reached a path writing an area to HA — a renamed device could relocate itself. (2026-08-19)
- When capping a name-derived score, cap it BELOW the consuming threshold and pin that relationship in a test naming the threshold, not the constant. Capping alone silently turns the consumer's branch into dead code; the honest move is to keep the signal, rename the category from an assertion (`incorrect_area_assignment`) to an observation (`name_area_mismatch`), and preserve the RANKING so the engine is still useful to the human it was always for. (2026-08-19)
- An existing drain prompt can be the SoT and still be BLIND to a whole wave: `homeiq-backlog-drain.md` (synced 2026-08-17) references zero of the TAP-61xx/62xx defect stories (one grep proved it).
