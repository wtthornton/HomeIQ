# orchestration-prompt learnings (project-scoped)

Append one-line lessons as you generate prompts. Keep them project-scoped; never
bleed across repos. This file is created once by the scaffolder and never
overwritten on upgrade — it's yours.

<!-- - Validation goals need a verified-correct-negative Done-when, or the loop chases an unreachable target. (2026-06-18) -->
- HomeIQ harness gates the loop must pre-satisfy: `save_issue` needs a `docs_validate_linear_issue` sentinel <30min (use the `linear-issue` skill), `list_issues` needs a prior `snapshot_get` (use `linear-read`), and all `tapps_*` MCP tools need `tapps_session_start` first. (2026-08-01)
- Merged != live here in a second way: several HomeIQ compose services declare `build:` with no `image:`, so `docker buildx bake` output is NOT what compose runs — rebuild via `docker compose up -d --build <service>` or the loop verifies a stale container. (2026-08-01)
- When the user has said "do not set anything up", split the Done-when between *agent implemented and tested* (fixtures/simulator) and *agent applied to the live system* (Autonomy hard-stop) — otherwise the loop mutates production to score itself green. (2026-08-01)
- Validation-goal caveat for audit tooling: an `audit` that reports every recipe NEEDS_APPLY is a correct pass, not a failure — state this explicitly or the loop chases an unreachable all-green. (2026-08-01)
- The skill's own files are tapps-managed (BEGIN/END markers) — customizing them without adding an `upgrade_skip_files` entry in `.tapps-mcp.yaml` means the next `tapps_upgrade` silently reverts the work. (2026-08-01)
- The `uv run tapps-mcp memory search` CLI is broken in this project (raises `ValueError: MemoryStore requires a Postgres private_backend`) — emit the `tapps_memory` MCP tool call for brain recall, never the CLI form. (2026-08-01)
- Pair every must-reach-zero clause with a must-grow one drawn from the SAME work: "0 REST-registry callers" alone is satisfiable by deleting the callers, so it must carry "AND >= N services import the shared client". Same for "0 deviations" → "at >= N rows". (2026-08-01)
- When a sub-goal's correct outcome is sometimes *removal* (a frontend call with no backend route), say so in Guardrails under "caps must not fire on correct behaviour" — otherwise the verifier scores a correct deletion red and the loop re-adds dead code. (2026-08-01)
- Order a long migration cheapest-and-least-coupled first, and say why: a 6-hour run that truncates should leave whole services done rather than every service half-done. (2026-08-01)
- Rate limits are a correctness trap in sweep scripts: admin-api caps at 60 req/min and `verify-dashboard-contract.sh` paces at 1.1s, so the prompt must forbid lowering `CONTRACT_PACE` to "speed it up" — the resulting 429s look exactly like failures. (2026-08-01)
- Carry an explicit "out of scope — human-gated, do not attempt" list naming the blocked issue ids; a loop told only what to do will wander into the blocked work and burn the run rediscovering the gate. (2026-08-01)
- ALWAYS read the full open backlog (`linear-read` over the whole project) before scoping a prompt — scoping to "the issues this session produced" missed 5 of 6 open HomeIQ epics and ~37 stories, and got the ordering wrong: the foundational build/CI epic was invisible. (2026-08-01)
- Verify the foundation epic's claims with a grep before assigning wave order: "all 54 build contexts are `../..`" and "0 of 10 domain CI workflows trigger on pull_request" are what justify putting build decoupling first, and both took one command each. (2026-08-01)
- When a Done-when clause measures a count going DOWN (containers 58→11, repo-root contexts 54→0), pair it with a capability-preservation clause ("every retired service's capability proven reachable", ">=54 services still build") — otherwise the target is met by deleting the system. This is the mirror of the must-grow rule. (2026-08-01)
- Order destructive waves last and make each deletion an Autonomy hard-stop; a consolidation epic that runs before its replacement surface exists is an outage, not a refactor. (2026-08-01)
- Subagents spawned as `general-purpose` have write tools even when the prompt says "read-only" — one silently edited `health-dashboard/src/services/api.ts` during a prompt-writing turn. Check `git status` after any subagent fan-out, and use the `Explore` agent type (no Edit/Write) for genuinely read-only research. (2026-08-01)
- A `haiku` verifier asked an open-ended gating question ("any new CI failures from this PR?") returned a confident WRONG verdict — "NO NEW FAILURES" while a check on the exact changed path was failing because of the PR — and skipped the log-fetch it was explicitly told to run. The same model answering a narrowed question ("does the ruff-format step pass?") was correct. Tier by question shape: cheap for closed evidence-checkable questions, `opus` for anything gating. (2026-08-11)
- `effort` is a Workflow-only parameter: `Agent(...)` accepts `model` but not `effort` and inherits the session's. A prompt that writes "use high effort" on an Agent dispatch is a no-op — if per-step effort matters, that step must run inside a Workflow. (2026-08-11)
- Never trust a subagent's *conclusion* on a load-bearing question; re-derive it from the evidence it returned. The CI agent's verdict was wrong but its raw job-status table was correct — reading that table directly surfaced the one failing step that was genuinely mine. (2026-08-11)
- Before/after quality comparisons must confirm which branch the working tree is on: a post-merge `git checkout` of the old feature branch made "before" and "after" score identical files, producing a fake "no change" result. Identical scores to 4 significant figures is the tell. (2026-08-11)
- Emitted prompts must explicitly GRANT the research tools and name the required lookups; a prompt that omits this gets HA/library YAML written from recalled syntax. `tapps_lookup_docs` is Context7-backed and local-cache-first, so "conserve lookups" is never a reason to skip it. (2026-08-11)
- Research before designing, not after: one `tapps_research` call replaced a hand-rolled multi-sensor entity list with HA's Binary sensor group helper (any-on/all-off semantics for free) and surfaced that labels are first-class automation targets — which is what makes "adopt a new sensor with no automation rewrite" actually true rather than aspirational. (2026-08-11)
- For HA specifically, always confirm the automation schema generation before writing YAML: 2024.10+ uses plural `triggers:`/`conditions:`/`actions:`, and a prompt carrying the legacy singular form will lint clean and fail at runtime. (2026-08-11)
- **AgentForge is where this project's intelligence belongs.** A prompt that routes reasoning through a HomeIQ container (`ha-ai-agent-service`, `ai-core-service`, `ai-query-service`) is building the thing TAP-5300/TAP-5302 exist to retire. The split is pipeline+gateway: AF reasons (author/judge/analyse), HomeIQ acts (collect, call HA, lint, deploy, test, roll back). Check every emitted prompt for cognition that leaked into a consumer service. (2026-08-11)
- 17 `expert-*` agents are published platform-wide on AF (architecture, testing, security, performance, database, api-design, observability, ux, …) and cost nothing to author — consult them during planning and review, and record where the advice was rejected. Other consumer projects also carry their own domain experts (`web-store-wstore-expert-*`, `hearth-goods-hearth-expert-*`); HomeIQ has none yet, which is the gap worth closing. (2026-08-11)
- The `agentforge` MCP server caches `.env` at startup: after restoring or rotating `AGENTFORGE_API_KEY`, its tools keep returning `missing-bearer` until the server restarts, while `scripts/af.sh` and curl work immediately. Do not diagnose that as a bad key. (2026-08-11)
- AF workflow authoring traps worth restating in any emitted prompt: `kind: task` not `kind: agent`; `$input` refs — a `{{input}}` placeholder passes through **literally** and `spec_version: 2` strictness will not catch it; terminal state is `complete` not `success`; `output_schema` is enforced on the workflow node, not the agent frontmatter; publish agents before workflows or get a 422. (2026-08-11)
- `run_config_flow` raises `HAHumanGateRequired` on ANY `progress` step, but not every progress step is a human gate: ZHA's `form_new_network` is pure hardware I/O (~2.5 min, poll with empty POSTs until `create_entry`). Prompts wiring config-flow recipes must distinguish poll-able progress from genuine human gates, or formation gets mis-filed as HITL. (2026-08-11)
- When a live install already happened, the captured flow transcript IS the recipe spec — cite the real per-step payloads (e.g. ZHA `choose_serial_port` takes a plain `{"path": "socket://ip:6638"}`) instead of telling the loop to re-derive schemas from core source. Also encode the destructive inverse as a guardrail: re-running ZHA formation on a loaded entry orphans every paired device. (2026-08-11)
- HA label registry stores slug ids while HomeIQ's store keeps `prefix:name` strings; any recipe/prompt that round-trips labels must match by name OR slug before creating, else every re-apply mints `<slug>_2` duplicates. (2026-08-11)
- A generated prompt can already exist from a prior session (committed under prompts/) — check `git log prompts/` and grep before generating; regenerating a near-duplicate forks the SoT. The right move is execute-or-update, not re-emit. (2026-08-11)
- AF judge agents hallucinate findings against their own input: the org-manifest judge asserted 5 entities were "absent" that were present with the exact recommended labels. Every emitted prompt that dispositions judge findings must require a deterministic re-check against the artifact BEFORE amending — reject-with-evidence is a first-class disposition. (2026-08-11)
- AF expert invocations can return degenerate output ({"advice":"test"}) at full billed cost; retry once with an explicit anti-placeholder instruction before falling back to codebase-convention reasoning. (2026-08-11)
- The tapps quality gate's maintainability category is module-length-dominated (radon MI ~0 past ~800 lines): plan NEW recipe/feature code as small cohesive modules re-exported from the legacy hub file, or the gate fails on size alone and tempts a suppression. Name-matched test files (test_<module>.py) are what the test-coverage category detects. (2026-08-11)
- Engine apply() halts later phases on any BLOCKED_ON_HUMAN in the current phase — a full-stack converge stops at the HACS gate before phase 6. Scope live converges per-phase (curl body {"phase": N}) so the halt is a finding, not a lost run. (2026-08-11)
- When a companion agent is still filing tickets mid-generation, put the pending ids in Unverified assumptions with a self-healing confirm step — then resolve them in-session the moment the filing notification lands, so the emitted prompt ships with concrete ids. (2026-08-12)
- A long-lived (>600k-token) goal-loop agent becomes disproportionately vulnerable to 529 Overloaded kills; the burndown prompt caps runs and checkpoints to brain per wave so a fresh session resumes cheaply instead of resuming the giant transcript. (2026-08-12)
- Physical-world steps (pairing buttons, sensor placement, switch wiring) are a distinct Autonomy hard-stop class: the loop must surface them as readiness gates and wait, never simulate or skip — 2026-08-12's manual run is the reference protocol (now on TAP-5946). (2026-08-12)
