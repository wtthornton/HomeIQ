## Loop

- **State:** wayfind resume (`tapps_memory` search) · `git rev-parse --short HEAD` ·
  last handoff · per-story Linear status via `get_issue` · brain recall of prior
  attempts on the current sub-goal.
- **Decide:** lowest-numbered sub-goal not yet verifier-green. Fog reappears (a
  story contradicts an ADR, a mechanism is undecided) → hard-stop, name it.
- **Execute:** dispatch the story to the committed mechanism + tier. Research
  BEFORE code that touches an external surface (grants below).
- **Verify (independent):** invoke the Workflow tool with
  `.claude/workflows/appliance-ship-verify.js`, args = the sub-goal's VAL rows
  (id, shape, cmd, expected, file:line anchors, environment quirks — ports, the
  fixture container name, auth source) **and the pinned SHA** (verifiers use
  `git show <sha>:<path>` / `git grep <sha>`, never working-tree reads — the
  orchestrator may have moved branches). Verifiers refute; empty `observed_output`
  = FAIL by construction. The verifier's verdict advances the loop.
- **On fail (expected-fail loop):** structured handoff → scoped fix sub-goal →
  re-execute → re-verify. ≤ 3 validation rounds per sub-goal, then escalate once
  (opus `/goal` drive), then stop with a diagnosis. Never weaken the contract.
- **Record:** completed · undone · commands + exit codes · issues ·
  failure-and-why → brain (`tapps_memory`), each iteration.
- **Context hygiene:** targeted `grep`/`git show` over full re-Reads; carry a
  compact state summary, never transcripts.
- **Print every iteration:**
  `SCORE: <vals-green>/30 VAL · sub-goal <k>/13 · round <a>/3 · iteration <i>/36 · orch-spend <p>% · e2e:<PASS|—>`
- **Checkpoint (shift boundary):** each sub-goal boundary or ~50% context —
  whichever first. `/tapps-handoff-session`, then the declared-checkpoint block
  below (operator types `/clear`; an agent cannot invoke `/clear` itself).
- **Repeat or stop:** until Done-when holds. Caps: **36 iterations** AND **2M
  tokens**, cumulative across shifts, read from the handoff — a checkpoint never
  resets them.

## Failure handling

- Failed verify → diagnose (actual error + state + brain recall) → hypothesis →
  fix → retry *differently*. ≤ 3 distinct strategies per sub-goal, escalate once,
  then stop with a concise diagnosis. Repeating the same action on the same error
  is forbidden.
- Expected-fail is the design: first verify failure on non-trivial work is normal.
- Verify fixes by re-running the FAILURE condition (recreate the exact absent
