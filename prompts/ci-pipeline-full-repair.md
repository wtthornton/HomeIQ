## Loop

- **State:** `tapps_session_start`; `tapps_memory` recall (`action="search"`) for prior attempts;
  `git log --oneline master..HEAD`; last SCORE line; `scripts/ci-baseline.json`.
- **Decide:** lowest-numbered sub-goal not yet verified. Within SG3/SG9/SG11, take the **cheapest
  service with the fewest failures first** — a truncated run should leave whole services done,
  not all services half-done.
- **Execute:** the committed mechanism above. One service per commit.
- **Verify (independent):** spawn a **fresh-context verifier subagent (frontier)** told to
  **refute** the claim — re-run `scripts/ci-local.sh` for that service itself rather than trusting
  the executor's narration. Default to "not done" on doubt. The **verifier's** verdict advances the loop.
- **On fail (expected-fail fix loop):** record structured handoff → scope a **narrow** fix
  sub-goal → re-execute → re-verify. **≤3 validation rounds per sub-goal**, then escalate once,
  then stop with a diagnosis. Never weaken the contract, delete a test, or add skip/xfail to go green.
- **Record:** completed · undone · commands+exit codes · issues · failure-and-why → `tapps_memory`
  (`action="save"`), at every sub-goal boundary.
- **Context hygiene:** prune stale reads each iteration; targeted `grep`/`sed -n` over re-Reading
  whole files; carry a compact state summary, not raw pytest transcripts. This is a 10-hour run —
  a full test log re-read is the top context sink here.
- **Repeat or stop:** until Done-when. Caps: **60 iterations** AND **~10 hours wall / the session
  token budget**, whichever first.

## Guardrails

- Termination: Done-when above; caps 60 iterations AND ~10h/token budget.
- **Less-tests-is-more during the work:** run only the touched service's suite (`-q`, then `--lf`).
  **No whole-fleet test run before SG13.** SG13 is the single full regression.
- **Anti-deletion / must-grow:** every "failures → 0" clause is paired with **per-service**
  "collected >= SG0 baseline" (plus the >= 5,500 / >= 43-service sanity floor). Green-by-deletion
  is a FAIL, and a fleet-wide total alone is not sufficient — it can hide one gutted service.
- **No green-by-suppression:** no `# noqa`, no `type: ignore`, no `@pytest.mark.skip`/`xfail` to
  dodge a real failure, no `try/except: pass`, no lowering a coverage gate, no adding rules to
  ruff `ignore`. If the honest fix is out of scope, **stop and say so.**
- **Caps must not fire on correct behavior:** (a) adding `ON_ERROR_STOP=1` in SG4 turning the
