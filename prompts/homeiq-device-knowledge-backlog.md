## Loop

- **State.** Read before acting: brain recall, the last structured handoff, the
  current SCORE from live queries, the wave ledger. Never re-derive a number you
  already measured this iteration.
- **Decide.** Take the lowest-numbered wave that is not verifier-green. One wave
  per iteration. If a wave is blocked, record why and move to the next
  *independent* one — waves 5 and 6 depend on nothing in waves 1–4.
- **Execute.** On the mechanism and tier committed in the Plane map. No
  improvising a different mechanism because it seems faster.
- **Verify (independent).** Spawn a **fresh-context verifier subagent** (`opus`)
  briefed to **refute** the wave's proof. It re-runs the deterministic check
  itself and confirms the container was rebuilt after the edit. **Name the
  weakness you already suspect and tell it to attack that specifically** — a
  verifier told "check this" confirms; one told "refute this claim" investigates.
  It defaults to "not done" on any doubt. Its verdict, not the executor's claim,
  marks the ID.
- **Never trust a subagent's conclusion on a load-bearing question** — re-derive
  it from the evidence it returned. A confident wrong verdict over a correct
  evidence table has already happened on this project.
- **On fail (expected-fail fix loop).** The first verify failing is normal.
  Record a structured handoff, scope a **narrow** fix sub-goal against the
  verifier's actionable gaps, re-execute, re-verify. **≤3 validation rounds per
  wave**, then escalate once, then stop with a diagnosis. Never widen a VAL
  threshold or delete an assertion to go green.
- **Record.** Structured handoff to brain **every wave**: completed · undone ·
  commands with exit codes · issues found · whether the procedure was followed ·
  what failed and why. A long-lived loop is disproportionately vulnerable to 529
  kills past ~600k tokens — checkpoint per wave so a fresh session resumes cheaply
  instead of resuming a giant transcript.
- **Context hygiene.** Prune stale file reads each iteration. Prefer `grep -n` or
  a `sed -n 'A,Bp'` slice over re-Reading a file you already read. Carry the
  compact SCORE forward, not raw transcripts. Delegate any read spanning more
  than ~3 files to a subagent that returns a summary — use the **`Explore`** agent
  type for genuinely read-only work, because `general-purpose` carries write tools
  and has silently edited a file during a read-only brief.
- **Repeat or stop.** Loop until Done-when holds. **Caps: 30 iterations AND 2M
  output tokens.** At either cap, stop and print a diagnosis with the final SCORE.

## Test strategy (minimize full regression)

- **Per-edit:** `mcp__nlt-build__tapps_quick_check(file_path=...)` on the edited
  Python file.
- **Per wave:** the owning service's tests **by explicit path**.
- **Blast radius, not the whole tree:** `tapps_diff_impact` or
  `tapps_validate_changed(file_paths="a.py,b.py", include_impact=true)` — always
  pass `file_paths`; auto-detect scans every changed file and is very slow here.
- **Known collection conflict:** `libs/homeiq-ha` and
  `domains/device-management/ha-setup-service` both expose a `tests` package. Run
  them in **separate** pytest invocations or collection fails on `tests.path_setup`.
- **Known environment failures:** ~35 pre-existing failures in the
  device-intelligence suite are DNS/auth issues from running outside the compose
  network (`Temporary failure in name resolution` on the `postgres` host). Diff
  against a `HEAD` worktree baseline before calling any of them yours.
- **Frontend:** `health-dashboard` carries ~120 pre-existing `tsc` errors, so
  type-check is **not** a gate — gate on `vite build` plus targeted vitest.
- **The quality gate scores whole files**, and its maintainability category is
  module-length-dominated (radon MI collapses past ~800 lines). Plan new code as
  small cohesive modules; name-matched `test_<module>.py` files are what the
  test-coverage category detects. Judge your diff, not the file's history.

## Guardrails

- **Termination:** the Done-when condition; caps **30 iterations AND 2M output tokens**.
- **Independent verification.** Creator ≠ verifier, every ID, no exceptions.
- **Caps must not fire on correct behavior.** The three sub-100% targets are
  deliberate; an explicit, reasoned exclusion counts as covered.
- **No fan-out of coupled coding.** Reads and research fan out to 6; **code edits
  stay serial**, one service at a time, in this session.
- **`effort` is a Workflow-only parameter.** `Agent(...)` accepts `model` but not
  `effort` and inherits the session's. Writing "use high effort" on an Agent
  dispatch is a no-op — if per-step effort matters, that step runs in a Workflow.
- **MQTT is deletion, never configuration.** If a step is about to add a broker,
  an MQTT integration or a Z2M topic, it is wrong. Zigbee is ZHA.
- **A friendly name is never identity and never a decision input.** No join on a
  name, no area inferred from a name, no group membership matched by name. Watch
  the one-hop launder — Hue room groups list member *names* and look like
  independent corroboration. Ask of every rule: **would a rename break this?**
- **Two evidence vocabularies.** `device_knowledge_claims` uses five classes
  (`measured | upstream_source | vendor_doc | community | inferred`) and its CHECK
  rejects the atlas's four (`attestation`, `unverified`). Do not mix them, and do
  not *remap* one onto the other — that invents a provenance nobody asserted.
- **`REQUIRED_PROVENANCE` is enforced server-side before persistence:** `measured`
  needs `method`; `upstream_source` needs `source_ref` **and** `source_version`;
  `vendor_doc` and `community` need `source_url`. A `source_ref` does not satisfy
  `vendor_doc`.
- **AF workflow traps:** `kind: task` not `kind: agent`; `$input` refs — a
  `{{input}}` placeholder passes through **literally** and `spec_version: 2`
  strictness will not catch it; terminal state is `complete` not `success`;
  `output_schema` is enforced on the workflow node, not the agent frontmatter;
  **publish agents before workflows** or get a 422.
- **AF experts can degenerate.** An expert invocation can return placeholder
  output (`{"advice":"test"}`) at full billed cost — retry once with an explicit
  anti-placeholder instruction, then fall back to codebase-convention reasoning.
  AF judge agents also hallucinate findings against their own input: **re-check
  every finding deterministically against the artifact before amending**;
  reject-with-evidence is a first-class disposition.
- **Scope.** Writes only in `/home/wtthornton/code/HomeIQ` and the `homeiq` AF
  project. Reads may go anywhere. No writes to sibling repos or other AF projects.
  Only TAP-6391 … TAP-6402 — do not touch other issues.
- **Harness compatibility.**
  - `PreToolUse` on all `nlt-*` tools requires `tapps_session_start` first —
    Sub-goal 0, every session, including after a compact.
  - `PostToolUse` on `docs_validate_linear_issue` writes a sentinel; `PreToolUse`
    on `save_issue` **blocks** without one < 30 min old. Always validate
    immediately before saving.
  - Linear **read** gate: `tapps_linear_snapshot_get` before any `list_issues`,
    same team/project/state/label/limit or the keys do not align.
  - `PostToolUse` on `Edit|Write|MultiEdit` runs `tapps-post-edit.sh`, and the

- **Discipline.** Root-cause, never a workaround. **No green-by-suppression** —

## Autonomy

- Act on every reversible, in-scope step. No "should I proceed?" checkpoints —
  the existence of this prompt is the authorization.
- Irreversible or outward step → produce the **reversible precursor** (draft PR,
  staged diff, written proposal) and keep going. A draft PR is not a stop.
- **Hard-stop once**, batched and with a recommendation, only for: the Linear
  OAuth probe failing (Sub-goal 0 — user-only, not self-healing); **rewriting git
  history** for TAP-6399, which is irreversible and outward; a validation contract
  that turns out to be *wrong* (stop and ask — never quietly rewrite Done-when to
  match a broken implementation); a projected next-step cost above the ceiling; or
  genuine fog reappearing.
- Physical-world steps (re-pairing a device, moving hardware) are their own
  hard-stop class: surface them as readiness gates and wait — never simulate.

## Failure handling (diagnose, don't repeat)

On a failed verify: read the actual error, inspect real state, recall prior
failures from the brain, form a **specific** hypothesis, then retry with something
changed. Re-running the same command on the same error is forbidden. **≤3 distinct
strategies per wave**, then escalate once, then stop and surface a diagnosis.

Traps this codebase has already sprung, worth checking before deep debugging:

1. A "gap" a health check reports may be a **false expectation** rather than
   missing work — verify the check against a second source before building to it.
2. A gate that iterates an **empty collection** passes vacuously; every
   `for x in collection: check(x)` needs a non-empty assertion beside it.
3. A NOT NULL column can carry **zero information** — `GROUP BY` before trusting
   any column a decision depends on.
4. Prove a gate is wired by **breaking it**, never by grepping for a module name.
5. An always-red CI check carries no signal — diff against `master` head first.
