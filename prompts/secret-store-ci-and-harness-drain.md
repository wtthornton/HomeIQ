## Orchestrator discipline  (the top session coordinates; it does NOT do the work)

**This session's job is to dispatch, read verdicts, and checkpoint — nothing else.**
Every file edit, every build, every log trawl, every full-file read happens in a
subagent or a Workflow whose context is disposable. The orchestrator's context is the
one thing that cannot be recovered once it fills, so it must stay cheap.

**The orchestrator MAY:** read `git status` / `git rev-parse`, call `get_issue`, read a
subagent's returned summary, write the handoff, print the SCORE line, decide the next
sub-goal.

**The orchestrator MUST NOT:** open a source file it is about to have edited, run
`docker compose build`, trawl `gh` job logs, read `learnings.md` in full, or apply an
`Edit`. If you find yourself about to `Read` a file larger than ~200 lines, **stop and

### Verifier tier follows the PROOF SHAPE — not a uniform max

Setting every verifier to `opus` is token waste that buys nothing on a proof an exit
code already settles. Tier by what the verifier actually has to decide:

| Proof shape | Tier | Why |
|---|---|---|
| **Deterministic** — exit code, item count, string present/absent, test-count line | `haiku` / `low` | It re-runs the command and pastes output. It cannot fabricate an exit code, and the raw output is the evidence. |
| **Comparative** — did the right thing change? is this the same failure as before? | `sonnet` / `medium` | Needs to hold two states side by side. |
| **Semantic** — is this a workaround? is the failure mode correctly named? could this break a running deploy? | `opus` / `high` | Judgement, and judgement is exactly where a cheap model returns confident-wrong. |
| **Anything gating an irreversible step** — merge to master, delete, force-push | `opus` / `high` | Regardless of shape. Non-negotiable. |

Applied to this run's contract:

| VAL | Shape | agentType | model | effort |
|---|---|---|---|---|
| VAL-001 compose exits 0, 39 services | deterministic | `general-purpose` | `haiku` | `low` |
| VAL-002 job reaches Trivy step | deterministic | `general-purpose` | `haiku` | `low` |
| VAL-003 `exit-code` ≠ `'0'`, matrix = 11 | deterministic | `general-purpose` | `haiku` | `low` |
| VAL-004 two `AuthManager`s verify each other | deterministic | `general-purpose` | `haiku` | `low` |
| VAL-005 absent config = **named** failure, not silent default | **semantic** | `general-purpose` | **`opus`** | **`high`** |
| VAL-006 `env.required` matches what the code reads | comparative | `general-purpose` | `sonnet` | `medium` |
| VAL-007 ≥ 431 tests still pass | deterministic | `general-purpose` | `haiku` | `low` |

That is 5 × `haiku` + 1 × `sonnet` + 2 × `opus` instead of 8 × `opus` — and the two that
genuinely need judgement get *more* effort than a uniform pass would have given them.

**Cheap-model rule (still binding):** `haiku` answers closed, evidence-checkable
questions and **never renders a verdict that gates an irreversible step**. Re-derive any
load-bearing conclusion from the evidence it returned — a `haiku` verifier here
previously returned a confident *wrong* verdict ("NO NEW FAILURES") while a check on the
exact changed path was failing, though its raw job-status table was accurate.
**Read the evidence, not the summary.** For every `haiku` row above, the verifier's
required output is the *pasted command output*, and the orchestrator reads that output —
not the agent's conclusion sentence.

- **State:** wayfind resume recall → `git status` + `git rev-parse --short HEAD` →
  `get_issue` for the ticket in play → brain recall of prior attempts via
  `mcp__nlt-memory__tapps_memory` (never the broken CLI) → last handoff.
- **Decide:** pick the lowest-numbered sub-goal not yet verified. Never invent decide
  work; if fog reappears, stop and `/tapps-wayfind`.
- **Execute:** the action, on the committed mechanism + tier from the Plane map.
- **Verify (independent):** invoke the Workflow tool with
  `.claude/workflows/secret-store-ci-verify.js`, passing
  `args: { sha: "<the SHA just landed>", only: ["VAL-00x", …] }` for the VAL IDs this
  sub-goal claims. The script pins every verifier to that SHA, sets **model + effort per
  proof shape**, runs them in parallel, and returns structured verdicts — so the
  orchestrator reads a roll-up, never a transcript.
  - Read `blocking[]` and `all_pass`. **Read `observed_output`, not `reasoning`**, for
    every `haiku`-tier verdict — the pasted command output is the evidence; the
    conclusion sentence is not.
  - `green_by_suppression: true` on any verdict is a **hard fail** regardless of the
    verdict field — it means the proof was satisfied by removing what it measures.
  - The workflow's verdict, not the executor's claim, advances the loop.
  - **Pin the verifier to a SHA** when the orchestrator may switch branches — hand it
    the SHA and tell it to use `git show <sha>:<path>` / `git grep <sha>` rather than
    reading the working tree. A prior verifier read `HEAD` mid-checkout and saw
    `414 passed` instead of `431` because the file did not exist on that branch.
  - **Name the weakness to attack.** For SG2: "refute that the placeholder `.env`
    actually resolves on the *runner's* Compose version, not just locally." For SG3:
    "refute that removing the fallback cannot break a running deployment." A verifier
    told "check this" confirms; one told "refute this specific claim" investigates.
- **On fail (expected-fail fix loop):** record a structured handoff → scope a narrow fix
  sub-goal → re-execute → re-verify. **≤ 3 validation rounds per sub-goal**, then
  escalate once, then stop with a diagnosis. Never weaken the contract to go green.
- **Record:** completed · undone · commands + exit codes · issues · procedures followed?
  · failure-and-why → brain.
- **Context hygiene:** prune stale reads each iteration; targeted `grep` over a full
  re-`Read`; carry a compact state summary, not raw transcripts.
- **Print every iteration:**
  `SCORE: <VAL green>/7 · sub-goal <k>/6 · round <a>/3 · iteration <i>/30 · orch-spend <pct>% · lane-A <running|done>`
  — `orch-spend` is the share of tokens burned in **this** session rather than in
  subagents. It is the delegation health metric: past **15 %** you are doing work that
  belongs in an agent. Delegate harder rather than explaining the number.
- **Checkpoint:** at each sub-goal boundary or ~50 % context — whichever first.
- **Repeat or stop:** loop until **Done-when** holds. Caps: **30 iterations** AND
  **~600 k tokens** — both **cumulative across shifts**, read from the handoff, never
  reset by a checkpoint. (Past ~600 k a loop becomes disproportionately vulnerable to
  `529 Overloaded` kills; checkpoint before that, do not push through it.)

## Checkpoint protocol (context shift boundary)

- **Lane:** **declared checkpoint** — this runs in an interactive orchestrator session,
  so the loop prints the block below and the operator types `/clear`. The loop
  **cannot** issue `/clear` itself: built-in CLI commands are not skills or tools, and
  a prompt that says "run `/clear`" silently no-ops while context keeps growing.
- **Trigger:** sub-goal boundary, or ~50 % context — whichever first.
- **Write:** `/tapps-handoff-session` → `.tapps-mcp/session-handoff.md`.
- **Resume:** `/tapps-continue-session`.
- **Carry-forward (must survive the clear, or the guardrails stop binding):**
  - Current sub-goal + the VAL IDs it must turn green
  - Attempt count vs cap — **cumulative**, e.g. `round 2 of 3`
  - Budget spent — **cumulative**
  - Strategies already tried and refuted, and why
  - The exact resume line from "How to run (cold start)"
- **On resume, re-verify before acting:** the handoff is a pointer, not a proof.
  Re-check `git rev-parse --short HEAD`, PR state, and
  `git merge-base --is-ancestor HEAD origin/master`. A handoff summarises the *last
  thing it did*, not the whole diff — one `gh pr diff --name-only` +
  `gh pr view --json commits` before trusting any PR-scope claim. The independent
  verifier still runs; a checkpoint never replaces it.

## Autonomy

- Act on every reversible, in-scope step — no "should I proceed?" checkpoints. Branch
  creation, commits, draft PRs, file edits, and Linear updates inside
  TappsCodingAgents/HomeIQ are all reversible and in scope: **just do them.**
- Irreversible/outward step → produce the reversible precursor (draft PR, staged diff,
  written proposal) and continue; the human reviews async. **A draft PR is not a stop.**
- **Hard-stop once** (batched, with a recommendation via `AskUserQuestion`) only for:
  - Merging to `master`, force-push, deleting a branch, or any history rewrite.
  - **A cross-project write** (any Linear team/project other than
    TappsCodingAgents/HomeIQ; any repo other than HomeIQ).
  - **Any step that would require a workaround** — swallowing an exception, skipping or
    disabling a test, silencing a linter/type-checker, hardcoding a value to force a
    pass, or leaving a stub. Stop and report blocked instead.
  - **Any step that reaches green by suppression** — reverting Trivy `exit-code` to
    `'0'`, downgrading severity, or shrinking the scan matrix.
  - The Linear plugin being unauthenticated (OAuth is user-only, not self-healing).
  - Projected next-step cost exceeding the ceiling (≈ USD 20 unless pre-authorized).
  - The validation contract itself turning out to be wrong — do **not** silently rewrite
    Done-when to match a broken implementation.

## Failure handling

- On failed verify: diagnose (read the actual error + inspect state + brain recall)
  → form a specific hypothesis → fix → retry with *something changed*.
- ≤ 3 distinct strategies per sub-goal; then escalate once (more capable model or a
  different approach); then stop with a concise diagnosis.
- **Repeating the same action on the same error is forbidden.**
- Expected-fail: the first verify failure is normal for non-trivial work — scope a
  narrow fix sub-goal, do not reopen the whole feature and do not weaken the contract.
