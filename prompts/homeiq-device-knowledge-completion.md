## Loop

- **State.** Read before acting: brain recall (`tapps-mcp memory search`,
  including `memory_group=wayfind` if any hits), the last structured handoff, the
  current SCORE line from live queries, and the sub-goal ledger. Never re-derive a
  number you already measured this iteration.
- **Decide.** Take the lowest-numbered sub-goal that is not verifier-green. One
  sub-goal per iteration. If a sub-goal is blocked, record why and move to the
  next *independent* one — SG7 and SG8 do not depend on SG2–SG6.
- **Execute.** On the mechanism and tier committed in the Plane map. No
  improvising a different mechanism because it seems faster.
- **Verify (independent).** Spawn a **fresh-context verifier subagent** (frontier
  tier) whose brief is to **refute** the sub-goal's proof. It re-runs the
  deterministic check itself — the curl, the SQL, the pytest — and confirms the
  container was rebuilt after the edit. It defaults to "not done" on any doubt.
  Its verdict, not the executor's claim, marks the ID.
- **On fail (expected-fail fix loop).** The first verify failing is normal, not a
  crisis. Record a structured handoff, scope a **narrow** fix sub-goal against the
  verifier's actionable gaps, re-execute, re-verify. **≤3 validation rounds per
  sub-goal**, then escalate once, then stop with a diagnosis. Never widen a VAL
  threshold or delete an assertion to go green.
- **Record.** Structured handoff to the brain every checkpoint: completed ·
  undone · commands with exit codes · issues found · whether the procedure was
  followed · what failed and why.
- **Context hygiene.** Prune stale file reads each iteration. Prefer a targeted
  `grep -n` or a `sed -n 'A,Bp'` slice over re-Reading a file you already read.
  Carry the compact SCORE line forward, not raw transcripts. Delegate any read
  that would dump more than ~3 files to a subagent that returns a summary.
- **Repeat or stop.** Loop until Done-when holds. **Caps: 25 iterations AND
  1.5M output tokens.** At either cap, stop and print a diagnosis with the final
  SCORE line — do not silently continue.

## Test strategy (minimize full regression)

Full-tree pytest is not a gate here and running it wastes the budget. Instead:

- **Per-edit:** `mcp__nlt-build__tapps_quick_check(file_path=...)` on the edited
  Python file.
- **Per sub-goal:** the owning service's tests **by explicit path** —
  `.venv/bin/python -m pytest domains/ml-engine/device-intelligence-service/tests/test_discovery_service.py -q`
  (verified: 14 passed in 0.57s).
- **Blast radius, not the whole tree:** `mcp__nlt-build__tapps_diff_impact` or
  `tapps_validate_changed(file_paths="a.py,b.py", include_impact=true)` — always
  pass `file_paths` explicitly; auto-detect scans every git-changed file and is
  very slow here.
- **Known collection conflict:** `libs/homeiq-ha` and
  `domains/device-management/ha-setup-service` both expose a `tests` package. Run
  them in **separate** pytest invocations or collection fails on
  `tests.path_setup`.
- **Behavioral truth is the live stack**, not a mock: `data-api`'s suite is fully
  mocked and cannot reproduce schema-state bugs, and `health-dashboard` carries
  ~120 pre-existing `tsc` errors so type-check is not a gate — filter to your own
  files and gate on `vite build` plus targeted vitest.
- The quality gate scores **whole files**, so a small diff to a legacy service can
  "fail" on pre-existing debt. Judge your diff, not the file's history.

## Guardrails

- **Termination:** the Done-when condition; caps **25 iterations AND 1.5M output
  tokens**.
- **Independent verification.** Creator ≠ verifier, every ID, no exceptions. A
  sub-goal the executor calls done and no verifier confirmed is **not** done.
- **Caps must not fire on correct behavior.** The three sub-100% targets in
  Done-when are deliberate. An explicit, reasoned exclusion counts as covered.
- **No fan-out of coupled coding.** Reads and research fan out to 6; **code edits
  stay serial**, one service at a time, in this session.
- **CPU ceiling.** Max 6 concurrent agents. No container rebuild during a fan-out.
- **MQTT is deletion, never configuration.** If a step is about to add an MQTT
  broker, an MQTT integration, or a Z2M topic, it is wrong. Zigbee is ZHA.
- **A friendly name is never identity and never a decision input.** No join on a
  name, no area inferred from a name, no group membership matched by name. Watch
  for the one-hop launder — Hue room groups list member *names* and look like
  independent corroboration. Ask of every rule: would a rename break this?
- **Two evidence vocabularies.** `device_knowledge_claims` uses five classes and
  its CHECK will reject the atlas's four. Do not mix them.
- **Scope.** Writes only in `/home/wtthornton/code/HomeIQ` and the `homeiq` AF
  project. Reads may go anywhere. No writes to sibling repos or other AF projects.
- **Harness compatibility.**
  - `PreToolUse` on all `nlt-*` tools requires `tapps_session_start` first —
    Sub-goal 0, every session, including after a compact.
  - `PostToolUse` on `Edit|Write|MultiEdit` runs `tapps-post-edit.sh`, and the
    nlt-build server nudges a quality check after every edit. **Adopted with a
    modification:** run `tapps_quick_check` per edited Python file, but batch
    `tapps_validate_changed` to the sub-goal boundary rather than per edit —
    per-edit full validation would dominate the budget on a multi-file sub-goal.
  - The `Stop` hook writes completion-gate telemetry to
    `.tapps-mcp/.completion-gate-violations.jsonl` in warn mode. Adopted as-is.
  - Linear write/read gates apply **only** if this loop files issues. It is not
    required to. If it does, route through the `linear-issue` / `linear-read`
    skills — a raw `save_issue` or `list_issues` call is a rule violation.
- **Memory.** Recall at the start of every iteration; record a structured handoff
  at every checkpoint, failures included.
- **Discipline.** Root-cause, never a workaround. **No green-by-suppression** —
  never skip a test, add `# noqa` / `# type: ignore`, swallow an exception, or
  hardcode a value to pass. Right-sized: the simplest change that fully solves it.
  Match the surrounding code's conventions. No silent scope creep.

## Autonomy

- Act on every reversible, in-scope step. No "should I proceed?" checkpoints — the
  existence of this prompt is the authorization.
- Irreversible or outward step → produce the **reversible precursor** (draft PR,
  staged diff, written proposal) and keep going. A draft PR is not a stop.
- **Hard-stop once**, batched and with a recommendation, only for: a `converge`
  that would write something un-restorable to HA; a validation contract that turns
  out to be *wrong* (stop and ask — never quietly rewrite Done-when to match a
  broken implementation); a projected next-step cost above the ceiling; or genuine
  fog reappearing.
- `POST /api/v1/init/converge` is **backup-gated by design** — running it is
  in-scope and reversible. Running it with `only=<recipe>` scoped to the recipe you
  are working on is preferred over a bare phase sweep.

## Failure handling (diagnose, don't repeat)

On a failed verify: read the actual error, inspect real state, recall prior
failures from the brain, form a **specific** hypothesis, then retry with something
changed. Re-running the same command on the same error is forbidden. **≤3 distinct
strategies per sub-goal**, then escalate once (stronger model or a different
approach), then stop and surface a concise diagnosis.

Two traps this codebase has already sprung, worth checking before deep debugging:
an always-red CI check carries no signal (diff against `master` head before
triaging), and a passing local `docker compose config` does not predict the runner.
