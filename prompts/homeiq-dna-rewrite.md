**Cheap-model rule.** `haiku` answers closed, evidence-checkable questions and renders
**no** verdict that gates a VAL. A `haiku` verifier returned a confident wrong verdict
on an open-ended gating question in this project before. If a cheap agent's answer is
load-bearing, re-derive the conclusion from its returned evidence.

**`agentType` is a permission boundary.** `general-purpose` holds Edit/Write even when
the prompt says read-only — one silently modified a file in this repo. Use `Explore`
for genuinely read-only work, and run `git status` after any `general-purpose` fan-out.

SG1–SG3 stay serial in-session: a small number of ordered, stateful changes against
one live system and one schema. Fanning them out is the documented worst fit.

## Loop

- **State:** `tapps_memory` recall (wayfind + prior attempts) → VAL coverage → last
  handoff → live HA state → AF publish state → `git status`.
- **Decide:** lowest-numbered sub-goal whose VALs are not all green.
- **Execute:** on the committed mechanism + tier above.
- **Verify (independent):** fresh-context verifier (`general-purpose`, `opus`,
  `xhigh` in a Workflow) prompted to **refute** the proof by re-running the check
  itself. Default to "not done" on doubt. The verifier **reports gaps, does not fix**.
- **On fail:** structured handoff → narrow fix sub-goal → re-execute → re-verify.
  **≤3 validation rounds per sub-goal**, then escalate once, then stop with a
  diagnosis. Never weaken a VAL to go green.
- **Record:** completed · undone · commands+exit codes · issues · expert advice and
  disposition · failure-and-why → `tapps_memory`.
- **Context hygiene:** prune stale reads each iteration; targeted grep over full
  re-Read; carry a compact state summary, not raw transcripts.
- **Repeat or stop:** until Done-when. Caps: **14 iterations** AND **~600k tokens**.

## Guardrails

- Termination: Done-when; caps 14 iterations AND ~600k tokens.
- **Caps must not fire on correct behavior.** A room-inference gene that **abstains**
  on a weak signal is a **pass**, not a failure. A verification verdict of
  **unverifiable** is a correct outcome. A tracker count going **down** because
  dead code was deleted is the goal, not a regression. A service returning zero rows
  is a **finding**.
- **Must-grow pairs every must-shrink.** "Zero name/area bypass call sites" is
  satisfiable by deleting callers — pair it with "≥N services still write names
  successfully through the gateway". Same for the tracker deletions: pair with
  "verification verdicts are persisted and readable".
- **Intelligence belongs in AgentForge.** Do not add LLM-calling logic to a HomeIQ
  container — that is the direction TAP-5300/TAP-5302 retire. HomeIQ collects, calls,
  deploys, measures. Genes reason. Check every diff for cognition that leaked into a
  consumer service.
- **Never write HA YAML, a template function, or a service call from memory** — look
  it up first. A hallucinated schema that lints clean and fails at runtime is the
  likeliest cause of a bad run.
- **Never trust a friendly name.** Two identically-modelled dimmers on this instance
  had swapped names and wrong areas; `area_entities("office")` did not return the
  switch that powers the office. Verify a device by ieee, by its LED-bar identity
  test, or by behavioural correlation — never by its label.
- No fan-out of coupled writes — SG1/SG2/SG3 serial.
- **Never print the HA token or the `afp_*` key.** Do not read `.env` / `.env.*`.
- `--env-file .env` on every single-service compose command.
- **No green-by-suppression:** do not relax a linter rule, shorten a timing
  assertion, or drop an assertion to pass. `enable_service_validation` currently
  defaults **false**, so a "validation passed" claim that relies on service checks is
  not evidence until that flag is on.
- Scope: HomeIQ repo + AF project `homeiq` + the live HA. **Writes to the AgentForge
  *platform* repo or its Linear project are out of scope** — those are the owner's
  call and TAP-6060 already exists.
- Discipline: root cause not workarounds; right-sized; durable; match repo
  conventions; no silent scope creep.

## Autonomy

- Act on every reversible in-scope step. Editing HomeIQ code, authoring and
  publishing genes, enabling a default-off flag, and deploying an automation are all
  reversible (SG0 baseline + versioned rollback).
- **Hard-stop once, batched, with a recommendation, only for:** deleting a table or
  a service directory · changing an `entity_id` slug · any write to the AgentForge
  platform repo or its Linear project · replacing the human-approval gate on a
  chromosome that can unlock a door or disarm an alarm · projected next-step cost
  above ceiling.

## Failure handling

- On failed verify: diagnose (real error + live state + brain recall) → hypothesis →
  fix → retry with *something changed*. Never re-run the same call on the same error.
- Max **3 distinct strategies** per sub-goal, then escalate once, then stop with a
  concise diagnosis. If the **contract** is wrong, stop and ask — do not rewrite
  Done-when to match a broken implementation.
